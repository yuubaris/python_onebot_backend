# python_onebot_backend
（Python + Flask + SQLAlchemy + SQLite）

一个简单的小程序：通过 WebSocket 连接 OneBot 11 服务端，具备前端管理页面，
支持配置群聊白名单、识别群聊用户身份，并处理以 `/` 开头的指令。
内置 `/签到`、`/武具店`、`/购买`、`/出售`、`/地下城`、`/挑战` 等指令与多级货币体系。

## 功能特性

- **连接 OneBot WS 服务端**：以客户端身份连接 OneBot 的**正向 WebSocket**（主机/端口/路径/授权 Token/消息格式/角色可配置），自动断线重连
- **消息格式**：数组（接收与发送均使用消息段数组格式）
- **角色**：Universal（同一连接同时支持 API 调用与事件推送，路径建议 `/`）
- **群聊白名单**：管理页面可增删/启停白名单群，仅白名单内的 `/` 指令会被处理
- **用户身份识别**：记录群成员的 QQ 号与昵称（优先群名片）
- **命令处理**：消息以 `/` 开头进入命令分发，当前支持：
  - `/签到`：每日签到（每用户每天只能 1 次），随机奖励——
    - **99.4%** 概率获得 **50~99 铜币**
    - **0.5%** 概率获得 **3 银币**（=300 铜币）
    - **0.1%** 概率获得 **1 铜币**
    - 连续签到天数会延续（昨日未断则累加）
  - `/余额`：查看当前资产与持有装备数
  - `/武具店`：查看可购买的装备（价格档 50→45000 铜币，共 14 档指数递增，封顶 4 金币 50 银币）
  - `/购买 商品名`：消耗铜币购买装备（**不能赊账**，铜币不足拒绝购买）
  - `/出售 商品名`：出售装备，获得**购买价 60%** 的铜币
  - `/地下城 进入 / 状态 / 退出`：地下城冒险（见下文）
  - `/挑战 @对方`：发起对战，纯随机 50/50 胜负，三条文字演出（间隔 2 秒），赌注结算（见下文）
  - `/帮助`：查看可用命令
- **货币体系**（内部统一以最小单位"铜币"存储）：
  ```
  100 铜币 = 1 银币
  100 银币 = 1 金币
  100 金币 = 1 王国币
  100 王国币 = 1 圣王国币
  ```
- **消息频率限制**（可配置）：按「群 × 用户」统计 "/" 指令频率（如 15 条 / 60 秒），超出后提示「发送消息过快，请在 N 秒后再试」，冷却期内该用户再次发送的消息被静默过滤、不再提示
- **B 站直播间监控**：绑定群号，轮询 B 站公开 API（每 60 秒），直播间开播/下播自动推送到绑定群；可配置启用/禁用
- **B 站 UP 主动态监控**：绑定 UP 主 UID 到群号，队列式轮询动态接口（每项间隔 3 分钟），检测到新动态自动推送（UP 名/类型/内容/时间/链接）；可配置启用/禁用
- **前端管理页**：连接状态、连接配置、消息频率限制、**直播间监控**、**动态监控**、群白名单管理、用户资产列表、签到记录、**装备库**、**地下城**实时状态、运行日志

## 装备系统（武具店）

装备数据保存在 **`equipment.json`**（项目目录内，直接编辑即可维护，程序启动后按文件修改时间自动重载）；
数据库中只记录用户持有的装备 **id**（`user_item` 表），装备完整属性统一从 JSON 读取。

每件装备包含字段：

| 字段 | 说明 |
| --- | --- |
| `id` | 唯一标识（如 `short_sword`） |
| `name` | 名称（如 短剑） |
| `type` | 类型：`weapon` 武器 / `shield` 盾牌 / `armor` 防具 / `robe` 法袍 / `accessory` 饰品 |
| `attack` | 攻击力 |
| `defense` | 防御力 |
| `hp` | 生命值 |
| `mp` | 魔力值 |
| `agility` | 敏捷 |
| `intelligence` | 智力 |
| `price` | 标准价格（铜币） |

价格采用**指数式分档**（每档约 ×1.7 拉开差距），从 **50 铜币** 一直涨到 **4 金币 50 银币**（=45000 铜币），共 30 件：
`50铜 → 75铜 → 1银20铜 → 2银 → 3银50铜 → 6银 → 10银 → 17银 → 30银 → 52银 → 90银 → 1金50银 → 2金60银 → 4金50银`。

武具店/购买/出售提示均按货币体系**自动换算显示**（如 45000 铜币显示为「4 金币 50 银币」，不会写成「45000 铜币」）。

- `/购买 商品名`：消耗铜币购买；**铜币不足无法购买（不能赊账）**
- `/出售 商品名`：获得购买价 **60%** 铜币（向下取整）

## 对战系统（/挑战）

- **玩法**：`/挑战 @对方`，纯随机 **50/50** 胜负（装备不参与判定），发送 3 条文字演出消息（每条间隔 **2 秒**）：甲出招 → 乙反击 → 终结+胜负结算
- **赌注**：基准 = max(全服资产中位数 × 3%, **500 铜币**)
  - 挑战方（发起者）败 → 支付 基准 × **1.2**
  - 被挑战方败 → 支付 基准 × **0.8**
  - 赢家通吃；**不能赊账**——输家资产不足时按全部资产支付
- **次数**：发起方每天限 **3 次**；被挑战方不限次
- **限制**：不能挑战自己；未注册用户无法挑战；地下城内禁止挑战
- **不赊账**：输家资产不足时**按全部资产支付（资产清零）**，赢家仅获得输家实际支付的金额，不存在赊账

## 未知指令封禁

- 系统**累计记录每个用户发送的未知指令次数**
- 前 **3 次**：正常提示「未知指令，发送 /帮助 查看可用命令」
- **第 4 次（超过 3 次）**：直接向群里发送 **`beat.jpeg`** 图片（项目根目录，可替换），并提示不再响应
- **第 5 次起**：该用户的未知指令被**静默过滤**（不提示、不发图），但有效指令不受影响

## 地下城系统

- **进入条件**：持有任意 1 件装备
- **进入后限制**：地下城内**仅允许 `/签到`、`/余额`、`/帮助` 与 `/地下城`（退出/状态）**，其他任何指令都会被拒绝
- **层数进度（幂函数曲线，防数值膨胀）**：第 1 层总进度 **1000**，随时间流逝自动削减，推进速度按【公式】：
  ```
  (攻击力 × 2 + 敏捷 × 1.5 + 智力 × 1.25 + 魔力值 × 1.2) × (1 + 防御力 / 400) × (1 + 生命值 / 600)
  ```
  每个用户**单独核算**，进度实时持久化，离线/断连期间也按真实时间差补算
- **层难度曲线**（第 n 层总进度）：`1000 × n^0.75`（幂函数，远慢于旧指数曲线，后期不膨胀）
- **金币产出**（按 **5 秒** 为单位核算，未满 1 铜币自动累积）：
  - 第 1 层：每 60 秒 1 铜币
  - 第 n 层每秒产币：`(1/60) × n^0.6`（增速低于难度曲线，更稳健）
- **属性规则**：
  - 初始属性：攻击 5 / 防御 2 / 生命 20 / 魔力 5 / 敏捷 5 / 智力 5
  - **同类型装备只取在【公式】中收益最大的 1 件**（按装备自身属性代入公式计算收益分），不同类型可叠加

## 直播间监控（B 站开播/下播）

- **原理**：轮询 B 站公开 API（`getRoomBaseInfo`，无需登录/Token），每 **60 秒**一次，检测 `live_status` 变化
- **判定规则**：仅 `live_status == 1`（直播中）视为开播；**轮播（2）不视为开播**
  - `0/2 → 1`：开播通知
  - `1 → 0/2`：下播通知
- **通知内容**：
  - 开播：直播间标题 / 主播名 / 开播时间 / 直播间链接
  - 下播：直播间标题 / 主播名
- **绑定规则**：一个群最多绑定 **1** 个直播间；一个直播间可绑定多个群（1 对多）
- **管理**：管理页「直播间监控」卡片可 添加（群号 + 房间号 + 备注）/ 停用 / 启用 / 删除 / 立即检测；卡片内设有**独立监控日志区**（实时显示轮询、开播/下播、增删启停等记录，每 3 秒自动刷新）
- **首次监控**只记录当前状态、不通知，避免误报；网络异常跳过本轮、不更新状态
- 备注字段可选（未填时主播名/标题取 B 站接口返回）

## UP 主动态监控（B 站新动态推送）

- **原理**：轮询 B 站公开动态接口（`/x/polymer/web-dynamic/v1/feed/space`），取 UP 主最新动态 id 并与上次记录比对
- **轮询策略**：**队列式串行轮询**——多个 UP 主时逐个轮询、每项间隔 **320 秒**（如 A→320s→B→320s→A…）；仅 1 个 UP 主时每 320 秒一次。拉大单 UP 请求间隔，规避 B 站风控
- **登录态 Cookie（必需）**：B 站动态接口对未登录 IP 有严格风控（-352/412），需在 `bili_cookies.txt`（Netscape 格式）中放入**登录后的 Cookie**（含 SESSDATA）。可安装浏览器插件「EditThisCookie」导出 `bilibili.com` 的 Cookie 数组，手工转成 Netscape 格式写入该文件；SESSDATA 过期（约 1 年）后需重新导出替换。检测到 SESSDATA 时跳过自动种 Cookie
- **防风控**：请求用系统 curl.exe（TLS 指纹接近浏览器）+ 登录 Cookie + Referer + 浏览器 UA；命中风控（-352/412）自动进入 300 秒冷却，期间不再请求该接口
- **设计参考**：借鉴 HarukaBot / bili-monitor / bilibili-notify 等开源项目的动态订阅轮询思路（记录最新动态 id 防重复推送）
- **判定规则**：最新动态 id 变化即视为有新动态；一次轮询内出现多条时按时间顺序逐条推送
- **通知内容**：UP 主名 / 动态类型（转发/投稿视频/图文/文字/专栏/音频）/ 内容（文字或标题）/ 发布时间 / 动态链接；**图文动态会下载正文配图（最多 3 张）到本地 `tmp/` 后随消息发送**
- **绑定规则**：一个群可绑定**多个** UP 主；一个 UP 主可绑定多个群（多对多）
- **管理**：管理页「动态监控」卡片可 添加（群号 + UP 主 UID + 备注）/ 停用 / 启用 / 删除 / 立即检测；卡片内设有**独立监控日志区**（实时显示轮询、新动态、增删启停等记录，每 3 秒自动刷新）
- **首次监控**只记录最新动态 id、不通知，避免误报历史动态；网络/接口异常跳过本轮、不更新状态

## 配置连接

在管理页「连接配置」中填写（对应 OneBot 实现的配置）：

| 配置项 | 说明 | 默认 |
| --- | --- | --- |
| 主机 | OneBot WS 服务端 IP | `127.0.0.1` |
| 端口 | OneBot WS 服务端端口 | `6700` |
| 路径 | 连接路径（Universal 用 `/`） | `/` |
| 授权 Token | OneBot 配置的 access_token（无则留空） | 空 |
| 消息格式 | `array`（数组） | `array` |
| 角色 | `universal`（推荐） | `universal` |

「消息频率限制」可在管理页独立配置：

| 配置项 | 说明 | 默认 |
| --- | --- | --- |
| 启用 | 是否开启频率限制 | 关闭 |
| 窗口内最多消息数 | 统计窗口内 "/" 指令的最大条数 | `15` |
| 统计窗口（秒） | 频率统计的时间窗口 | `60` |
| 提示冷却时长（秒） | 超出限制后提示的作用时长，冷却期内静默过滤 | `60` |

保存后会自动重连。连接成功后在管理页顶部看到"已连接"。

> 以 go-cqhttp / NapCat 为例，需要在 OneBot 实现中启用正向 WebSocket：
> ```yaml
> ws:
>   enable: true
>   host: 127.0.0.1
>   port: 6700
> ```

## 使用流程

1. 打开管理页，配置连接并确认"已连接"
2. 在「群聊白名单」中添加目标群号
3. （可选）在「直播间监控」中添加要监控的 B 站房间号并绑定群号，开播/下播自动推送
4. 在白名单群里发送：
   - `/签到`：每日签到，随机获得铜币/银币
   - `/武具店`：查看装备 → `/购买 短剑` 购买 → `/出售 短剑` 出售
   - `/地下城 进入`：开始冒险（持有任意 1 件装备）
   - `/地下城 状态`：查看层数/进度/金币
   - `/地下城 退出`：离开地下城
   - `/踢 @对方`：合成"踢人"图片（你的头像 + 对方头像贴到底图，60 秒冷却）
   - `/余额`：查看资产

## 扩展新命令

在 `commands.py` 中新增一个处理函数，然后在 `COMMANDS` 注册表中登记即可，例如：

```python
def cmd_roll(user, group_id, args):
    return "🎲 掷出了 6"

COMMANDS = {
    # ...已有命令...
    "roll": cmd_roll,
    "掷骰子": cmd_roll,
}
```

## 说明

- 签到日期取服务器本机日期，建议将程序部署在中国时区（UTC+8）机器上
- **复读机**：白名单群里 2 个不同用户发送相同内容的消息后，机器人立刻复读一次；同一轮（60 秒窗口）内即使第 3 个、第 4 个用户继续发相同内容也不再复读，防止刷屏；同一用户重复发送不计入；命令消息（`/` 开头）不参与复读；窗口过期后自动重置
- 地下城进度/金币在任意指令触发时按真实时间差自动补算（惰性结算），无需常驻定时器
- **地下城进度保存**：`/地下城 退出` 会保存当前层数与剩余进度，之后 `/地下城 进入` 会**直达上次位置**继续冒险（例如上次在第 19 层剩 500 进度，下次进入仍从第 19 层剩 500 开始）；无保存进度时从第 1 层开始。管理页地下城表格会显示「保存进度」列；旧数据库首次启动自动补列（无需重建）
- `/踢 @对方`：发送者（踢人者）头像 120×120 圆形贴在底图 `images.jpg` 的 (400,98)，被 @ 者（被踢者）头像贴在 (75,34)，合成图保存到 `tmp/images_时间戳.jpg` 并作为图片消息发送到群；每个用户 60 秒冷却；头像来自腾讯官方 qlogo 直链（失败时用灰色圆形占位图）。回复文本中被 @ 者优先显示其**群名片/昵称**（机器人在白名单群里所有消息都会记录发送者名片；对被 @ 用户还会异步查询一次 `get_group_member_info` 刷新名片），无记录时显示 QQ 号
- 所有命令回复通过 `send_group_msg` 以数组格式发送
- 连接异常会自动每 3 秒重连一次，可在「运行日志」中查看
