# QQ 官方机器人接入设计文档（群聊地下城机器人）

> 目标：将本系统（python_onebot_backend）从 **OneBot11 协议 + 第三方实现（NapCat/Lagrange）** 迁移为 **QQ 开放平台官方机器人** 形式，以"QQ 官方机器人"身份加入 QQ 群使用。
> 版本：v1.0 · 2026-09-09 · 基于 QQ 开放平台官方文档（bot.q.qq.com，2026-08/09 版）
> 官方文档入口：https://bot.q.qq.com/wiki/ · https://q.qq.com

---

## 1. 现状与本方案对比

| 维度 | 现状（OneBot 第三方） | 目标（QQ 官方机器人） |
|---|---|---|
| 接入协议 | OneBot11 正向 WebSocket，连接 NapCat/Lagrange | 官方网关 WebSocket（`wss://api.bot.qq.com/websocket/`）+ OpenAPI（REST）发消息 |
| 账号性质 | 普通 QQ 号（有风控/封号风险） | 平台官方机器人账号（稳定、不被风控） |
| 进群方式 | 普通 QQ 号拉群 | 群主/管理员在群设置中添加官方机器人 |
| 群消息接收 | 全部消息 | 默认仅 **@机器人** 消息；群主可在群设置开启"获取群内全部消息" |
| 消息发送 | OneBot `send_group_msg` | `POST /v2/groups/{group_openid}/messages`（文本/markdown/ark/media） |
| 用户标识 | QQ 号（数字） | **openid**（不透明字符串，事件内获取） |
| 群标识 | group_id（数字） | **group_openid**（不透明字符串） |
| 频控 | 无平台级限制（依赖第三方） | 被动回复 5 分钟内每条消息最多 5 次；机器人维度 60 qpm；单群 20 qpm |
| 部署要求 | 需公网内可连的 OneBot 服务端 | WebSocket 模式**无需公网 IP/域名**（Webhook 模式才需 HTTPS 公网） |
| 稳定性 | 依赖逆向协议，有封号风险 | 官方开放接口，稳定合规 |

**核心结论**：官方机器人方案对现有**业务代码（commands.py 命令逻辑）零改动**，只需新增/改造"消息接入适配层"（bot.py），把官方事件归一化为现有内部事件、把内部回复转译为官方消息格式。

## 2. 前置条件与资质要求

| 项 | 要求 | 说明 |
|---|---|---|
| 注册 | QQ 开放平台账号（QQ 扫码或邮箱注册） | 一个邮箱只能注册一个开放平台账号 |
| 主体认证 | **个人**：实名认证（姓名+身份证号+手机号，需与运营商实名一致） | 个人认证后可公开使用，机器人可进群数上限 **500 个** |
| | **企业**：营业执照 + 对公打款验证（1 元以下小额打款回填） | 全场景开放、部分高级接口需企业 |
| 机器人数量 | 单个开放平台账号最多创建 **6 个**机器人 | 可一个账号同时管理正式/测试机器人 |
| 未认证状态 | 机器人仅管理员本人可用，只能加入管理员为群主的群 | 正式使用必须完成认证 |

> 本系统为游戏娱乐机器人，**个人认证即可满足**需求（500 群上限远超实际使用）。

## 3. 平台侧详细操作流程

### 3.1 注册并认证

1. 打开 QQ 开放平台官网（https://q.qq.com ），选择 **QQ 登录**（扫码）或 **邮箱注册**。
2. 按向导完成 **完善账号信息**（邮箱/密码）。
3. **设置超级管理员**：填写超级管理员姓名、身份证号、手机号（接收验证码）、QQ 号——三者实名信息必须一致。
4. **填写主体资质**：
   - 个人：选"个人"主体，人脸/实名验证；
   - 企业：选"企业"，上传营业执照、统一社会信用代码，选"人脸认证"或"对公打款"验证（打款验证：3 天内收到腾讯对公小额打款，回填金额校验）。
5. 等待主体认证通过（个人即时/快速；企业打款约 1~3 天）。

### 3.2 创建机器人

1. 开放平台 → **机器人** → **我的机器人** → **创建机器人**。
2. 填写：头像、**昵称**（如"地下城冒险"）、**简介**（如"QQ 群地下城挂机冒险机器人：/地下城、/签到、/背包、/锻造、/炼金、/抽奖、/挑战"）。
3. **设置 AI 服务**：选择"稍后连接"跳过（我们是自主开发，不走 OpenClaw 等 AI 托管）。
4. 创建成功后进入机器人管理页，左侧导航：账号信息 / 服务范围 / 运营数据 / 高级设置 / 开发设置。

### 3.3 配置服务范围

1. **账号信息**：核对昵称/头像/简介。
2. **服务范围**：
   - **群聊开关：开启**（"允许机器人被添加到任意群聊使用"）——核心；
   - 好友（私域）/频道：按需开启（本系统仅群聊，可只开群聊）；
   - **隐私协议：必填并提交**（填写联系邮箱等，平台自动生成完整协议；未提交协议无法上线）。
3. **运营数据**：上线后查看消息数、活跃用户等。

### 3.4 开发设置（获取接入票据）

进入 **开发设置**：

| 配置项 | 值 | 用途 |
|---|---|---|
| AppID | 机器人 ID（如 1304899825） | 连接/签名必用 |
| AppSecret | 机器人密钥 | 换取 Access Token（**Token 直传鉴权已废弃**，必须用 Access Token） |
| Access Token | 由 AppID+AppSecret 换取 | WebSocket Identify 的 `token` 字段格式为 `QQBot {AccessToken}` |
| 消息 URL 配置 | 如需在消息中发 URL 必须先配置 | 否则含链接消息发送失败 |

### 3.5 沙箱配置（本地联调阶段，免审核）

1. 管理端 → **沙箱配置** → **QQ 群**：选择用于测试的 QQ 群（**≤ 20 人**）作为沙箱群。
2. 手机 QQ：打开该群 → **群设置 → 群机器人 → 添加测试机器人**（或管理端提供的入口）。
3. 沙箱环境特点：**不受消息频控限制**、不影响正式发布；私信暂不支持沙箱。

### 3.6 发布上线（审核）

1. 管理端 → **发布设置** → 填写：**指令列表**（本系统全部 `/命令` 及简介，见 §6）、**机器人自测报告**（官方模板 xlsx）、**第三方机器人隐私保护指引**。
2. 提交审核 → 等待 QQ 官方人工测试审核（个人主体私域机器人一般 **1~3 个工作日**）。
3. 审核通过后点击 **上线机器人** → 全平台可用。

> 上线前机器人仅沙箱群可用；审核期间可继续开发迭代，上线后再提交变更审核。

## 4. 开发侧接入设计

### 4.1 总体架构

```
QQ 客户端(群)
   │  @机器人 或 群设置开启全部消息
   ▼
QQ 官方网关  wss://api.bot.qq.com/websocket/
   │  WebSocket 长连接(事件: GROUP_AT_MESSAGE_CREATE / GROUP_ADD_ROBOT ...)
   ▼
【新增】qq_official.py ── 官方接入适配层
   │  事件归一化 → (group_openid, user_openid, text, msg_id)
   ▼
commands.dispatch_command(user, group_id, args, at_qqs)   ← 现有业务层,零改动
   │  回复文本 / 图片消息 dict
   ▼
【新增】qq_official.py 发送层
   │  POST https://api.sgroup.qq.com/v2/groups/{group_openid}/messages
   │  (msg_type=0 文本 / 7 富媒体 / 2 markdown)
   ▼
QQ 群
```

### 4.2 WebSocket 接入协议（官方网关）

1. **获取网关地址**：`GET /gateway/bot`（带 Authorization 头），返回 `wss://api.bot.qq.com/websocket/` + 建议分片数（本系统单连接，shards=1 即可）。
2. **建立连接** → 收到 `OpCode 10 Hello`（含 `heartbeat_interval`，如 45000ms）。
3. **鉴权**：发送 `OpCode 2 Identify`：

```json
{
  "op": 2,
  "d": {
    "token": "QQBot {AccessToken}",
    "intents": 33554432,
    "shard": [0, 1]
  }
}
```

   `intents = 1 << 25`（`GROUP_AND_C2C_EVENT`）：接收群聊@消息、机器人进群/退群事件。
4. 鉴权成功 → 收到 `READY`（含 session_id）；此后按周期发 `OpCode 1 Heartbeat`（d = 最近收到的 s 序列号）。
5. **断线重连**：连上后发 `OpCode 6 Resume`（token + session_id + seq），官方补发断线期间遗漏事件；记录 s 用于 resume。

### 4.3 需要订阅的群事件（intents = 1<<25）

| 事件 t | 含义 | 本系统用途 |
|---|---|---|
| `GROUP_AT_MESSAGE_CREATE` | 群里 @机器人 的消息 | **核心**：收到后提取文本调用 dispatch_command |
| `GROUP_ADD_ROBOT` | 机器人被添加到群 | 触发欢迎消息（可选） |
| `GROUP_DEL_ROBOT` | 机器人被移出群 | 清理群白名单 |
| `GROUP_MSG_REJECT / RECEIVE` | 群管理关闭/开启机器人通知 | 状态感知 |

> 默认仅收 **@机器人** 消息（本系统命令均以 `/` 开头，@ 前缀不影响解析：归一化时剥离 `@机器人` 段即可）。若群主在群设置开启"机器人可获取的群聊消息范围 = 获取群内全部消息"，则能收到非 @ 消息，体验与 OneBot 一致。

### 4.4 消息归一化（官方事件 → 内部事件）

新增 `qq_official.py`，把官方事件转成现有 `on_event` 需要的结构：

| 官方字段 | 内部字段 | 处理 |
|---|---|---|
| `d.group_openid` | group_id | 直接映射（群白名单存储改为 group_openid） |
| `d.author.id`（openid） | user 标识 | **openid 非真实 QQ 号**，需在 User 表新增 `openid` 列做映射（见 §4.6） |
| `d.content` | text | 剥离 `<@!openid>` 或 `<@openid>` 提及段、解析 CQ 等价富文本 |
| `d.id` | msg_id | 保存用于被动回复（发送时回填 `msg_id` + `msg_seq`） |
| `d.timestamp` | - | 备用 |

### 4.5 发送消息（OpenAPI）

| 场景 | 接口 | 参数要点 |
|---|---|---|
| 群聊文本回复 | `POST /v2/groups/{group_openid}/messages` | `msg_type=0`，`content` 文本；被动回复带 `msg_id`+`msg_seq`（同一 msg_id 不同 seq 不重复发送） |
| 图片（头像合成图 beat.jpg、images.jpg） | `msg_type=7` 富媒体 | 先调富媒体上传接口拿 `file_info`，再带 `media` 参数 |
| 增强展示（后续可选） | `msg_type=2` markdown / `3` ark | 抽奖、排行榜可升级为卡片 |

**关键限制（必须遵守）**：
- 群聊**被动回复有效期 5 分钟**，每条消息最多回复 **5 次**（本系统单命令单回复 + 挑战对战 3 条演出消息，均在限额内）；
- 机器人维度频控 **60 qpm**（个人/企业一致）、**单群 20 qpm**（本系统正常使用远低于此，但挑战对战 3 连发在密集使用时需注意）；
- 主动推送（非回复）：群聊**每月每群 4 条**，且需群主开启"机器人主动在群聊内发言"——**本系统全部为被动回复，不依赖主动推送**；
- 沙箱环境不受频控限制；
- 消息中含 URL 需先在开发设置-消息 URL 配置登记。

### 4.6 数据层改造（用户/群标识映射）

现有 `user_id`（QQ 号）与 `GroupWhitelist.group_id`（数字）在官方模式下拿不到，需迁移：

```sql
-- models.py 新增
ALTER TABLE user ADD COLUMN openid TEXT;           -- 官方 openid
ALTER TABLE group_whitelist ADD COLUMN group_openid TEXT;
CREATE INDEX idx_user_openid ON user(openid);
CREATE INDEX idx_gw_openid ON group_whitelist(group_openid);
```

- **新用户**：首次消息按 `openid` 建号（user_id 保留自增），`_user_title`/排名等逻辑不变；
- **老用户**（可选）：提供 `/绑定 QQ号` 指令把 openid 与既有 user_id 绑定，保留历史数据；不绑定的按新号从零开始（推荐先绑定，数据不丢）；
- **群白名单**：管理页新增"官方群 openid"录入；`GROUP_ADD_ROBOT` 事件可自动登记。

### 4.7 现有模块改动清单

| 文件 | 改动 | 工作量 |
|---|---|---|
| `qq_official.py`（新增） | 官方网关 WebSocket 客户端（鉴权/心跳/重连/resume）+ 事件归一化 + OpenAPI 发送层 | 核心新增 |
| `bot.py` | 保留 OneBot 客户端（可选双通道并存）；抽出 `send_group_message(group, text, image=None)` 通用接口 | 小 |
| `models.py` | User.openid、GroupWhitelist.group_openid 字段 + 索引 | 小 |
| `commands.py` | ensure_user 增加 openid 分支；/绑定 指令；@提及剥离（已有参数 at_qqs 机制可复用） | 小 |
| `app.py` | 启动时按配置选择连接方式（onebot / qq_official / 双通道）；管理页增加官方模式配置（AppID/AppSecret/沙箱开关） | 中 |
| `ratelimit.py` | 用户维度限流 key 改为 openid | 小 |
| `kick.py` 等头像合成 | 图片改为走富媒体上传接口（file_info）发送 | 中 |

> **commands.py 的 `/命令` 业务逻辑、地下城/锻造/炼金/抽奖/Boss 等全部零改动**——适配层只负责"收发消息"这一层。

## 5. 群内使用流程（面向群主/群友）

### 5.1 群主添加机器人（上线后）

1. 手机 QQ 打开目标群 → 右上角 **群设置** → **群机器人**；
2. 机器人列表/商店中搜索机器人昵称（如"地下城冒险"）→ **添加**；
3. 添加后建议在群设置 → 机器人详情中：
   - **机器人可获取的群聊消息范围** → 选 **获取群内全部消息**（这样 `/命令` 无需 @ 也能响应，体验与 OneBot 一致）；
   - **机器人主动在群聊内发言** → 按需开启（本系统不使用主动推送，可不开）。

### 5.2 沙箱群添加（上线前测试）

1. 管理端 → 沙箱配置 → 选择测试群（≤20 人）；
2. 手机 QQ：群设置 → 群机器人 → **添加测试机器人**；
3. 沙箱内联调所有 `/命令`，不受频控。

### 5.3 群友使用

- 群主开启"获取群内全部消息"后：直接发 `/地下城 进入`、`/签到`、`/背包`、`/挑战 @对方` 等（与现在完全一致）；
- 未开启时：发 **`@机器人 /地下城 进入`**（适配层自动剥离 @ 段）。

## 7. 实施步骤与验收清单

| 阶段 | 步骤 | 验收 |
|---|---|---|
| 1. 注册认证 | 开放平台注册 + 个人实名认证 | 管理端显示"已认证" |

| 5. 沙箱联调 | 沙箱群跑通全部命令（/地下城 全流程、图片消息） | 地下城进出一轮、挑战对战 3 条演出正常 |

## 8. 风险与注意事项

1. **openid 与 QQ 号隔离**：官方不返回真实 QQ 号，历史数据需 `/绑定` 迁移；建议上线前完成，避免玩家进度丢失。
2. **被动回复 5 分钟/5 次限制**：地下城长时间挂机后的战利品结算消息在 `/地下城 状态` 时触发——状态命令属于新消息的回复，不受旧消息限制，但**同一条消息不要连续回复超过 5 次**（挑战对战 3 条演出 OK，勿再加多段播报）。
3. **单群 20 qpm**：挑战对战连发 + 高频刷命令需留意；必要时为演出消息加节流。
4. **图片消息走富媒体**：beat.jpg/images.jpg 合成图需先上传拿 file_info；沙箱联调阶段务必验证图片链路。
5. **内容合规**：官方审核关注赌博/抽奖类玩法表述，抽奖/乞讨等指令简介建议中性化表述（"趣味抽奖""装备互助"），避免审核驳回。
6. **服务范围开关**：未开启"群聊"开关时机器人无法被添加；隐私协议未提交无法上线。
7. **双通道并存（可选）**：过渡期可 OneBot 与官方机器人同时在线、共用数据库，官方版验证稳定后再下线 OneBot，降低迁移风险。
