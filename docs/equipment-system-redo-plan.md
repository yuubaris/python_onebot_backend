## 一、背景与动机

### 1.1 推进速度公式（一切数值的地基）

```python
speed = (attack×2 + agility×1.5 + intelligence×1.25 + mp×1.2)
        × (1 + defense/400) × (1 + hp/600)
```

拆成两个部分：

| 部分 | 属性 | 权重 | 性质 |
| --- | --- | --- | --- |
| **输出主项** | 攻击 attack | ×2 | 物理主属性 |
| | 敏捷 agility | ×1.5 | 物理副属性 |
| | 智力 intelligence | ×1.25 | 魔法主属性 |
| | 魔力 mp | ×1.2 | 魔法副属性 |
| **生存乘子** | 防御 defense | 1+def/400 | 通用 |
| | 生命 hp | 1+hp/600 | 通用 |

- 物理线（攻+敏）合计权重 = 2 + 1.5 = **3.5**/属性点
- 魔法线（智+魔）合计权重 = 1.25 + 1.2 = **2.45**/属性点
- 防御、生命是**两职业通用**的乘区（对任意职业收益一致）

> ⚠️ 关键推论：同数值下物理线天然比魔法线更“值钱”（3.5 vs 2.45）。
> 要让两线收益相等，**魔法装备的智/魔数值必须显著高于同价位物理装备的攻/敏**。

### 1.2 现状问题清单（对应历轮需求）

| # | 你提出的问题 | 现状事实 |
| --- | --- | --- |
| P1 | 物理/魔法（战士/法师）不分线，可混搭 | `type` 只是“物品类别”，无职业/流派属性。武器(物理)+法袍(魔法)可同时生效叠加收益 |
| P2 | 数值未按公式设计，收益价格不齐 | 同一价格档物理与魔法装备“进度收益”差异很大（见 §4 实测） |
| P3 | 名称与分类错配、部位数不等 | ① `robe(法袍)` 里混入 `木杖/学徒法杖/贤者法杖`（名字叫杖、分类却是袍）；② 盾牌带攻击、法袍却算魔；③ 各 type 数量：weapon11/shield7/armor3/robe8/accessory9 —— **防具只有 3 件，不对称** |
| P4 | 装备数量不足 | 武器库 38 件 + 铁匠铺 10 件；价格档多数只有 1~2 件，防具断档严重 |

### 1.3 现有关键机制（重做时需保留或改造）

- **同类型只取公式收益最高 1 件**：`effective_stats()` 按 `type` 分组，每组取 `item_formula_score()` 最高分一件，再跨组叠加（武器取 1、防具取 1、法袍取 1……）。
- **数据库只存 id**（`user_item.item_id`），属性全部从 `equipment.json` / `forge.json` 读取，改 JSON 即生效（mtime 热重载）→ **数据迁移成本低**。
- 出售 = 购买价 60%；铁匠铺装备不可出售。
- 持有任意 1 件装备即可进地下城。

## 二、重做目标（需求确认 v3）

**装备系统两大成长轴**：
- **职业轴**（能穿哪一线）：战士(物理) / 法师(魔法)，不能混搭（v2 已定）。
- **阶级轴**（能用到多好）：通过晋升解锁更高阶装备（本轮新增）。

1. **职业系统**：玩家自主选择 **战士（物理）/ 法师（魔法）** 职业（**未来可扩展更多职业**），**不能混搭**两职业的输出加成。
2. **转职与引导**：`/转职` 命令切换职业；**新用户首次参与装备玩法时提示选职业**；**存量用户在代码生效后首次购买/锻造时提示转职**。
3. **购买限制（职业）**：非本职业专属武器**不可购买/锻造**（返回明确提示）。
4. **数值审计**：检查现有装备数值，修正明显**超模 / 拉跨**（收益与价格失衡）的装备。
5. **数值按公式对齐**：同一层级的战士/法师装备数值可以不同（因公式权重不同），但**推进收益大致相等**。
6. **同层级多选**：同一档位提供多件可选装备，数值侧重不同但收益相当（给玩家选择自由度）。
7. **名称与分类统一**（法杖即法杖、法袍即法袍）；两职业部位数量相等、一一对应；饰品通用。
8. **扩充装备数量**：武器库/铁匠铺按上述原则补齐。
9. **晋升系统**：按**地下城进度（层数）**判定达标，**消耗货币**晋升到更高**阶级**（Tier）。
10. **武器库改名**：`武具店 → 武器库`（`/武器库`），只展示**当前阶级及更高阶级**的装备。
11. **购买/装备阶级限制**：需晋升到**特定阶级**才能**购买并装备**对应装备。

## 三、核心设计（职业系统 + 晋升 v3）

### 3.1 职业模型：战士 / 法师（可扩展）

新增**职业**概念。装备仍以 `line` 标记归属，职业与 `line` 一一映射：

| 职业 | line | 输出主属性 | 说明 |
| --- | --- | --- | --- |
| `warrior` 战士 | `physical` | 攻击/敏捷 | 物理近战 |
| `mage` 法师 | `magic` | 智力/魔力 | 魔法施法 |

- 代码内置 `CLASSES` 注册表（`id → {名称, line, 可用type…}`），**未来新增职业只在此登记即可**。
- 装备字段 `line`：`physical`（战士专属）/ `magic`（法师专属）/ `any`（通用，两职业皆可）。
- 玩家职业存 DB（`User.profession`，空=未转职）；无 `line` 的旧装备按 `type` 兜底推断。

### 3.2 职业选择 / 转职流程（新用户 + 旧用户引导）

**转职命令**：`/转职 战士`、`/转职 法师`（无参查看当前职业与可选职业）。
职业可**随时免费切换**；切换后另一职业专属装备**保留在背包但不生效**（可正常出售）。

- **新用户**：首次参与装备玩法（首次 `/购买`、`/锻造`、进入地下城）且未转职 → 返回先导提示：
  「💡 你是新手冒险者，请先选择职业：`/转职 战士`（物理近战）或 `/转职 法师`（魔法施法）。」
- **存量用户**：代码生效后**首次执行 `/购买` 或 `/锻造`** 且仍未转职 → 同样先给转职引导，选择后才能购买/锻造职业专属武器。
- **未转职兜底**：进入地下城/结算时，输出收益按“物理组 vs 魔法组”**自动取更高一侧生效**（见 §3.4），
  保证存量玩家不因未转职而战力受损；转职后即严格锁定单职业。

### 3.3 部位体系：职业专属 + 通用（对称）

每职业 3 个专属部位槽 + 通用饰品槽，两侧数量完全对称：

| 槽位 | 战士（line=physical） | 法师（line=magic） | 通用 any |
| --- | --- | --- | --- |
| **武器槽** | `weapon` 剑/刀/锤/枪 | `staff` 法杖/权杖（**从 robe 拆出**） | — |
| **防具槽** | `armor` 重甲/铠（生存向） | `robe` 法袍/长袍（生存向） | 纯生存轻甲可 `any` |
| **副手槽** | `shield` 盾牌 | `focus` 法器（新增） | — |
| **饰品槽** | `accessory` 饰品 | `accessory` 饰品 | 两职业共用 |

要点：
- 武器→法杖、重甲→法袍、盾→法器 一一对称；`robe` 回归法袍，`staff` 拆出成法师武器，新增 `focus` 法器。
- **纯生存轻甲**（皮甲系，几乎无输出）标 `any` 两职业共用（D2）。
- `TYPE_NAMES` 新增 `staff=法杖`、`focus=法器`；前端装备库同步显示职业/类型列。

### 3.4 effective_stats 职业过滤（不能混搭的落地）

```
若玩家已转职（职业 line = L）：
  可用装备 = owned 中 [line == L 或 line == any]
若未转职（兜底自动择优）：
  物理可用组 = owned 中 [line=physical 或 any]
  魔法可用组 = owned 中 [line=magic 或 any]
  分别求两组总收益，取较高一组生效
任一组内：按 type 取公式收益最高 1 件，跨部位叠加（武器+防具+副手+饰品）
```

效果示例：某玩家持有 圣剑·王者(战士) + 混沌魔袍(法师)，
- 转职战士 → 只吃 圣剑·王者 + any；魔袍不加成。
- 转职法师 → 只吃 魔袍 + any；剑不加成。
- 未转职 → 自动取收益高的一侧。
**任何情况下都不可能同时吃到两职业的输出加成。**

### 3.5 购买 / 锻造职业限制（需求 1-②）

- **职业专属装备**（`weapon`/`staff` 及职业防具/副手）：**仅对应职业可购买/锻造**；
  未转职或职业不符 → 返回「❌ 这是{战士/法师}的装备，请先 `/转职 {战士/法师}` 后再购买。」
- **`any` 通用装备**（饰品、纯生存轻甲）与**本职业装备**：正常购买/锻造，不限制。
- `/出售` **不受职业限制**（已持有的任意装备均可出售）。
- 锻造配方同样按配方 `line` 做职业校验。

### 3.6 晋升系统：阶级 Tier（需求 2-①）

**两个成长轴之一“阶级轴”**：决定玩家能买到/能装备多好的装备。
**晋级称号**：每晋升一阶获得更酷炫的职业称号 = **前缀 + 职业名**（战士 / 魔法师），
如 见习战士 → 疾风战士 → … → 灭世战士（魔法师同理）。

**阶级分层草案 v1（初始假设）与校准结论**：经收益/升级速度测算（§3.6.1），
原草案存在「**解锁档偏低**（玩家到该层时已买得起更高档）」与「**晋升层门槛偏高**（爬层耗时过长）」双向失衡，
下表同时给出原值与本轮校准建议（实施时按最终装备表再微调）：

| 阶级 | 晋级称号（战士 / 魔法师） | 层数门槛（原→校准建议） | 可解锁装备档（原→校准建议） |

### 3.6.1 收益 × 升级速度 匹配度测算（本轮实测）

**测算模型**：玩家从 1 层一路推进，到每个阶级门槛用当时解锁档买最优全套（weapon+armor+shield+accessory），
扣除购装成本后结转现金；用真实产币公式 `(1/60)·n^0.6` 与推进公式累计。

**实测结果（关键行）**：

| 到达门槛层 | 累计在线(理想连续挂机) | 届时可用现金 | 现金能买的武器档 | 原草案解锁 | 判定 |
| --- | --- | --- | --- | --- | --- |
| 50 | ~1 h | ~700 铜 | ~600 | ≤350 | 略偏低 |
| 150 | ~12 h | ~9,500 铜 | ~9000 | ≤1000 | **偏低 ~9 倍** |
| 400 | ~28 h | ~33,000 铜 | ~26000 | ≤3000 | **偏低 ~9 倍** |
| 800 | ~62 h | ~107,000 铜 | 45000(封顶) | ≤9000 | **偏低，应全解锁** |
| 1600 | ~155 h | ~434,000 铜 | 45000 已封顶 | ≤45000 | 需铁匠承接 |
| 3000 | ~340 h | ~130 万铜 | — | ≤45000 | **门槛过高**（爬层太慢） |

**结论**：
1. **产币快于装备档扩容**：装备价格用 ×1.7 固定 14 档（50→45000），而产币 `n^0.6` 随层数增长 → 到 150/400/800 层时现金已远超草案解锁档（约 9 倍）。→ **解锁档应大幅上调**。
2. **晋升层门槛偏高**：理想连续挂机下到 1600 层需 ~155h、3000 层需 ~340h；若按真实断断续续玩法耗时更长 → 多数玩家永远到不了 T5/T6。→ **层门槛应整体下调**（体验节奏更顺）。
3. 上述为理想连续挂机估算，真实更慢 → 倾向**偏快的节奏**（下调门槛、上调解锁档），并在实施时用 `balance_check` 校准。

**称号设计要点**：
- 前缀主题与现有顶级装备呼应（苍穹之刃/神谕王冠/永恒之刃），成长感连贯；
- 职业后缀来自 `CLASSES` 注册表（战士/魔法师），**新增职业自动继承同一套前缀**（如 灭世游侠）；
- 玩家面板/消息展示完整称号（如 `⚔️ 烈焰战士 · Lv/Tier 2`），由 `tiers.py` 提供。

- 玩家初始 **T0**；用 `/晋升` 命令，满足「历史最高层 ≥ 门槛」且「货币足够」即可晋升到下一阶。
- **层数取历史最高**：`max(dungeon_layer, dungeon_cleared, saved_dungeon_layer)`（与铁匠铺/矿石资格同口径）。
- 晋升消耗货币：**推荐按货币体系“金币/王国币”级**（回收中后期盈余，见决策 D11）。

**装备 tier 字段**：每件装备新增 `tier`（0~6，对应上表）。锻造配方可给 tier 6，或在铁匠铺内部继续分档。

### 3.7 武器库（改名 + 阶级展示过滤）（需求 2-②/2-③）

- **命令改名**：`/武具店` → `/武器库`（保留 `/shop` 别名兼容），展示列表更名为“武器库”。

## 四、数值平衡方法（P2）

### 4.1 反推法：给定价格档 → 两线目标收益相同

设某价格档 P 的目标是“单件套入公式后的**收益分** = T”（T 含生存乘子）。

> 收益分即 `item_formula_score()`：`输出主项 × (1+def/400) × (1+hp/600)`。

对**同一档位**分别设计物理件与魔法件，使二者 T 相等：

| 项目 | 战士装备（物理线）示例 | 法师装备（魔法线）示例 |
| --- | --- | --- |
| 主属性分配 | 攻高、敏低（如 atk24 / agi4） | 智高、魔中（如 int28 / mp18） |
| 输出主项 | 24×2+4×1.5 = **54** | 28×1.25+18×1.2 = **56.6** |
| 生存向 | def4 / hp0 | def4 / hp6 |
| 收益分（约） | 54×1.01 ≈ **54.5** | 56.6×1.01×1.01 ≈ **57.7**（微调后≈54.5） |
| 价格 | 600 | 600 |

> 因为魔法权重低（2.45 < 3.5），魔法件需要**更大数值**才能平掉物理件收益，
> 这正是“数值看起来不同、但收益价格相等”的正确来源。

### 4.2 数值模板（建议直接套用，含锻造延伸）

按**价格档位**给每件装备定一个“预算”（预算 = 输出主项与生存属性按比例折算），
每个档位物理/魔法两版预算相同；具体分配比例（攻:敏 / 智:魔 / 防:命）固定规则化：

- 输出装（武器/法杖/副手）：约 **70% 预算 → 输出主属性**，30% → 生存（防/命）。
- 生存装（重甲/法袍）：约 **70% → 防御/生命**，30% → 少量输出主属性。
  - 纯生存位可 `line=any`，两线共用（如皮甲=通用轻甲）——减少重复件并强化“防具通用”。
- 饰品：`line=any`，混合属性（主项+生存兼顾，数值约为同档武器的 60~70%）。

> 详细数值表（38→若干件具体属性）在实施阶段产出，会在本文件 §6 追加“数值表链接/附表”。

### 4.2.1 档位数值示例（600 铜币档，方法演示）

以现有 `秘银剑`(600) 所在档为例，反推整档五件（战士武器/法师法杖/通用防具/法师法器/通用饰品），
令收益分 ≈ 秘银剑原收益分（约 54.5），物理/魔法/通用收益对齐：

| 装备 | 职业 | type | 攻 | 敏 | 智 | 魔 | 防 | 命 | 输出主项 | 收益分(约) |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 秘银剑（现） | physical | weapon | 24 | 4 | 0 | 0 | 4 | 0 | 24×2+4×1.5=**54** | 54×1.01 ≈ **54.5** |
| 秘银法杖（新增魔法对应） | magic | staff | 0 | 0 | 28 | 18 | 4 | 6 | 28×1.25+18×1.2=**56.6** | 56.6×1.01×1.01 ≈ **57.7** → 微调智/魔 |
| 皮甲→通用轻甲（现 armor 改 any） | any | armor | 0 | 0 | 0 | 0 | 12 | 15 | 0（纯生存） | 生存件收益随持有者总属性折算，价格档按生存预算定价 |
| 元素小法器（新增） | magic | focus | 0 | 0 | 6 | 10 | 14 | 20 | 6×1.25+10×1.2=**19.5** | 约 **20**（副手位，弱于武器） |
| 魔法披风（现 accessory） | any | accessory | 0 | 8 | 8 | 30 | 8 | 20 | 8×1.5+8×1.25+30×1.2=**58** | 约 **59**（饰品混合向） |

> 说明：示例中的“微调”在实施时通过校验脚本自动收敛到误差 <3%；生存件不追求与输出件同收益，
> 而是“同档预算”原则（生存件比输出件便宜或带通用性作交换，价格体系可微调档位）。

### 4.2.2 同档预算一致性检查（示例原则）

- 物理武器(54) ≈ 魔法法杖(≈54，靠更大智/魔数值弥补低权重)
- 生存件与法器、饰品按“预算×定位系数”折算，定位系数约定：
  武器 1.0 / 法杖 1.0 / 副手 0.55~0.6 / 防具与法袍(通用) 0.7~0.8 / 饰品 0.7（全通用）
- 校验脚本对每档断言：`战士武器收益 ≈ 法师法杖收益`（主检）且各件收益落档内预期区间。

### 4.2.3 同层级多选（需求 1-④）

同一价格档位提供**多件可选**装备，属性侧重不同、但收益大致相等：

- 例：600 档可给 2~3 把战士剑（偏攻 / 偏敏 / 均衡）+ 2~3 根法师法杖（偏智 / 偏魔 / 均衡）。
- 校验：同档任意两件 `收益分` 偏差 < **3%**，仅侧重不同 → 玩家按手感/后续定位选择。
- 这同时是 §6 扩充的标准：不是“每档一件”，而是“每档可多选、件件等价”。

### 4.3 用公式校验（验收标准）

每档任意战士/法师/通用件，套用 `item_formula_score()` 校验：

```
同档战士武器收益 ≈ 同档法师法杖收益 ≈ 同档通用件收益（误差 < 3%），且同档多件间亦 <3%
```

自动化校验脚本 `docs/equipment_balance_check.py`（开发期跑，不入库），防止改 JSON 后失衡。

### 4.4 数值审计：现有装备体检（需求 1-③）

实施第一步对现 **38 件（武器库）+ 10 件（锻造）** 逐件审计：

- 收益分 = `item_formula_score(item)`；再算“每铜币收益 = 收益分 ÷ 价格”用于同档横向比较。
- 判据：
  - **超模**：同档单位收益明显高于均值（>+15%）→ 削数值或提价；
  - **拉跨**：同档单位收益明显低于均值（<-15%）→ 增数值或降价；
  - **跨职业失衡**：同档战士武器 vs 法师法杖收益差 >3% → 对齐。
- 已知明显失衡（实施时脚本核实并补全）：
  - `贤者法杖`（600，智24/魔70 → 输出主项≈114）：同 600 档 `秘银剑`（攻24/敏4 → ≈54）约 2 倍，**超模** → 调整智/魔。
  - `圆盾`（50，攻8敏1 + 防10命5）：与同价 `短剑`（攻8敏1、无生存）相比白送生存，**偏超模** → 微调。
- 输出《现有装备数值修正表》（装备→现数值→修正后数值），作为 §6 目标数值表的输入。

### 6.3 矿石扩充（ores.json + 掉落联动，需求：矿石丰富种类）

**现状问题**：仅 6 种矿石（普通 铜/铁、稀有 银/秘银、传说 金/龙晶），对应 4 级锻造略单调；Boss 掉落池可选内容少。

**扩充方案**（配合锻造分级与 Boss 掉落，增加矿种与稀有度层次）：

| 稀有度 | 现矿种 | 扩充矿种（建议） | 主要用途 |
| --- | --- | --- | --- |
| 普通 | 铜矿石、铁矿石 | + **锡矿石**、+ **铅矿石**（或 玄武石） | 低阶锻造/兑换小价值 |
| 稀有 | 银矿石、秘银矿石 | + **精金矿石**、+ **星辰砂** | 中阶锻造（Lv2~Lv3） |
| 传说 | 金矿石、龙晶石 | + **圣辉石**、+ **龙魂晶** | 高阶锻造（Lv3~Lv4） |
| （新增）神话 | — | **星陨铁 / 混沌核 / 神谕石** | Boss 大 Boss + 顶级锻造（Lv4/毕业） |

- 数量：6 → **约 12~16 种**，按 稀有度/common→rare→legendary→myth 分 4 档（新增 myth 档时 `ore.py` 掉落概率表同步扩展）。
- 联动：
  - `ore.py` 掉落（400 层定时）与 **Boss 即时掉落**（`docs/dungeon-boss-plan.md` §4）都可掉新矿种；
  - 传说/神话矿由大 Boss、高层定时掉落产出 → 供给锻造 Lv3/Lv4 与晋升/顶级消耗；
  - `/背包` 展示与稀有度前缀（·/◆/✦ 及神话样式）同步扩展。
- **约束**：新增矿种不破坏既有配方消耗（旧的铜/铁/银/秘银/金/龙晶保留并继续可用）；新矿只用于新配方或作 Boss/兑换用途。

## 十、风险与注意（v3）

- **数据热重载**：equipment/forge 按 mtime 重载；`models.py`/`classes.py`/`tiers.py`/`commands.py`/`dungeon.py` 改动需重启进程生效。
- **存量职业为空 / 阶级为空**：未转职自动择优兜底；全员初始 tier=0，**无自动定阶**（老玩家不继承，均 `/晋升` 逐级提升，2026 口径）。
- **存量高阶装备**：老玩家若持有高阶装备（如 混沌魔袍 T5），因其重新从 T0 起步，需逐级 `/晋升` 达标后才能生效（短期可能“穿不上”，属预期，2026 口径）。
- **旧背包兼容**：line/tier/profession 缺失兜底推断；类型更名（robe 法杖→staff）自动重映射。
- **晋升货币回收平衡**：晋升费用若定太低无意义、太高卡成长；需与产币曲线（(1/60)·n^0.6）对齐测算（D11）。
- **武器库过滤体验**：只展示 tier≥当前时，需保证低阶玩家仍能看到“自己可买”的整段装备（展示其所在档全部），避免误判为商店为空。
- **平衡回归**：改数值后必须跑审计脚本，防止“卖装备加速”与跨职业失衡复发。
- **DB 迁移**：`profession`/`tier` 加列带默认值（空串 / 0），无需重建表、旧库自动兼容。
- **范围**：只动“重做后的新系统”，不动未提及的玩法。
