  （armor 归战士专属后，未转职稀有掉落仅剩通用饰品，转职引导更明确）
  （临时库冒烟通过）；T5 玩家偏向统计：大Boss T5占比~55% / 小Boss~46% / 精英~40%（2026-09-08）。

## 一、背景与目标

**现有地下城模型（重要前提）**：进入地下城后**自动推进**——
`settle_dungeon()` 按真实流逝时间用 `speed` 削减当前层剩余进度 `progress`，
归零即 `dungeon_layer += 1` 并重置 `progress = layer_total(新层)`；
停留期间持续产币；通关某层只是“推进过程中顺带经过”，**没有手动战斗、没有独立通关结算**。

**目标（本轮需求）**：
1. 在推进关卡中加入 **Boss 关**：每 10 层精英、每 50 层小 Boss、每 100 层大 Boss。
2. Boss 关对应关卡的**血量（= 该层总进度）提升**。
3. 通关 Boss 关时**随机掉落矿石或稀有装备**（稀有装备定义见下方“稀有装备·专属掉落体系”）。

### 1.1 稀有装备·专属掉落体系（需求澄清定稿）

| 要点 | 规则 |
| --- | --- |
| 来源 | **仅 Boss 关掉落**；商店（武器库/铁匠铺）**不出售** |
| 强度定位 | **优于同 tier 普通装备**，但**不超过 tier+1 的普通装备**（数值钳制） |
| 对应档位 | **掉落 Boss 层所在层数 → 对应 tier**（层越高掉越高级），按 §3.6 层门槛映射 |
| 职业/阶级 | 仍受职业(line)与玩家阶级(tier)约束（见 §4.3），掉落的必须能穿上 |
| 命名 | **独立专属名字**，不与商店/铁匠铺同名（见 §4.3 命名规则） |
| 展示 | 名称前标注 **✦ 星号** 与 **稀有** 字样（如 `✦ 星辰之怒(稀有)`） |
| 数据 | 独立 `rare_drops.json`（或 `boss_drops.json`）存放，**与商店表分离** |
| 定位用途 | 给挂机推进的“惊喜掉落 + 属性小突破”，替代性推进动力，非商店路径 |

## 二、Boss 分布与判定

> **✅ 已实现演进（v2.11.15~17，与下文 D-B 方案并存为最终口径）**：
> - **推进胜负判定（v2.11.15）**：仅**命名守关 Boss**（`bosses.json` 18 个）进度跑完后按战力胜率判定——胜率随 S/B0 升降、3% 保底；**失败 → 进度重置（重新攻略该关）、本关收益照常继续计算**，再次跑满进度判定成功才通关推进；精英/小Boss/无名字的整百层 Boss 进度跑完即通关、不判定。
> - **B0 锚定装备档（v2.11.16）**：命名 Boss 战力 **B0 = 穿满对应装备档的 S ÷ 1.327**（胜率 70% 锚点）——100→商店T1、200~300→T2、400~700→T3、800~1400→T4、1600~2500→T5、**3000→锻造Lv3、3600→锻造Lv4**（后段对应锻造装难度）；实现于 `dungeon.named_boss_b0`，主动 `/挑战` 与推进判定共用。
> - **档内层间梯度（v2.11.17）**：同档内 B0 线性插值——档首胜率 ≈85%（x=1.782）、档末 ≈70%（x=1.327），前面的 Boss 战力要求适当降低。

### 2.1 触发层号（层号从 1 起）

### 2.1 触发层号（层号从 1 起）

| 类型 | 触发层号 | 例子 |
| --- | --- | --- |
| 精英 Elite | `layer % 10 == 0` | 10,20,30,40,… |
| 小 Boss | `layer % 50 == 0` | 50,150,250,350,… |
| 大 Boss | `layer % 100 == 0` | 100,200,300,400,… |

**优先级（层号同时命中时按高者）**：
`大 Boss(100) > 小 Boss(50) > 精英(10)`
（如 100 层同时是 10/50/100 倍数 → 判为**大 Boss**；50 层同时是 10/50 → 判为**小 Boss**）

### 2.2 判定函数（放 dungeon.py）

```python
BOSS_ELITE_EVERY  = 10   # 精英
BOSS_MINOR_EVERY  = 50   # 小 Boss
BOSS_MAJOR_EVERY  = 100  # 大 Boss

def boss_type(layer):
    """返回该层是否为 Boss 关：None / 'elite' / 'minor' / 'major'"""
    if layer % BOSS_MAJOR_EVERY == 0:
        return 'major'
    if layer % BOSS_MINOR_EVERY == 0:
        return 'minor'
    if layer % BOSS_ELITE_EVERY == 0:
        return 'elite'
    return None
```

## 三、血量提升（Boss 层总进度）

### 3.1 血量倍率（D-B1 已定稿：精英 ×1.5 / 小Boss ×3 / 大Boss ×6）

当前每层总进度 `layer_total(n) = 1000 × n^0.75`。
Boss 层把该层**总进度放大**（等效 Boss 血量更厚、推进耗时更长、产币也略多）：

| Boss 类型 | 血量倍率（草案） | 说明 |
| --- | --- | --- |
| 精英 | ×1.5 | 小挑战 |
| 小 Boss | ×3 | 中挑战 |
| 大 Boss | ×6 | 大挑战 |

> 实现：`effective_layer_total(layer) = layer_total(layer) × (倍率)`；
> 仅 boss_type 命中时启用。产币仍按该层 `coin_rate`（停留更久 = 赚略多，作为补偿）。

### 3.2 推进/结算改动点

`settle_dungeon()` 的 while 循环中，`total` 改由 `effective_layer_total` 提供；
每次 `progress` 归零、进入下一层前，**检测“刚通关的这一层”是不是 Boss 层**，
若是则触发通关掉落（见 §4）。注意循环可能一次结算连过多层，需对每层都判。

**关键设计点（D-B2）**：Boss 掉落是"通关瞬间结算"，而不是像矿石那样按时间周期。
在循环内识别“本次循环从该层清零离开”的层号即可。
**✅ 设计定稿（D-B11 · 掉落生效时机 = 退出重进后下次进入才计入）**：
`settle_dungeon()` 的 `speed` 在 while 循环**外只计算一次**（结算开始时 `effective_stats`+`dungeon_speed`）。
Boss 掉落装备**写入 `user_item` 后背包立即可见**，但**本次结算不重算推进速度**（不打乱当前结算、实现简单）；
**退出地下城后下次进入**（`_dungeon_enter` 重新 `effective_stats`）时自动计入新装备 → 速度才生效。

配套体验（D-B13 · new！提醒）：
1. 掉落装备写入时打 **new 标记**（`UserItem.is_new=1`），背包/掉落播报显示 `new！`；
2. `new！` 语义 = “刚掉落、下次进入地下城后才生效”——玩家在背包可见，并知晓它尚未被计入推进；
3. **下次进入地下城并生效后自动清除 new 标记**（此时装备已真正计入推进速度）。

## 四、通关掉落（矿石 / 稀有装备）

### 4.1 掉落结构

每次通关 Boss 层，按概率掷骰，**二选一或都掉**（见决策 D-B3）：

- **矿石掉落**：直接调 `ore.grant_ores()` 写入 `user_ore`。
- **稀有装备掉落**：从**独立稀有掉落池**抽一件“玩家可用”的稀有装备写入 `user_item`（见 4.3 限制）。
  - 稀有装备**不在商店出售**（`/武器库`、`/铁匠铺` 都不卖），仅此处掉落获得。

### 4.2 概率与内容（D-B3/D-B4 已定稿，见上方「〇、实施落地记录」）

| Boss | 掉落概率 | 可能内容（定稿） |
| --- | --- | --- |
| 精英 | 100%（必掉） | 矿石：普通为主，少量稀有；小概率装备 |
| 小 Boss | 100%（必掉） | 矿石稀有度更高 + 装备概率提升 |
| 大 Boss | 100%（必掉） | 必掉矿石（含传说概率↑）+ 大概率稀有装备 |

> 倾向“Boss 必掉，但**内容随机**”——比“概率空手”体验好（挂机玩法避免挫败感）。

- 矿石稀有度：随层号提升（复用扩充后的 `ore` 表矿种：普通 铜/铁(+锡/铅) → 稀有 银/秘银(+精金/星辰砂) → 传说 金/龙晶(+圣辉石/龙魂晶) → 神话 星陨铁/混沌核/神谕石；见装备重做 §6.3 矿石扩充）；层号越高稀有/传说档概率越高。
- 稀有装备稀有度：随 Boss 类型与层号提升（见 4.3 层数→tier 映射）。

### 4.3 稀有装备定义与掉落约束（核心）

**稀有装备 = 商店买不到的 Boss 掉落专属装备**，三条铁律：

1. **不在商店出售**：`rare_drops.json`（独立池），`/武器库` `/铁匠铺` 一律不出现、不可购买。
2. **强度钳制**：稀有装备(同 tier) 的 `收益分` **高于该 tier 的普通顶配**，但 **≤ 该 tier+1 的普通装备**：
   ```
   普通同tier顶配  <  稀有(tier)  ≤  普通(tier+1)
   ```
   （由 `docs/equipment_balance_check.py` 校验断言，防超模/防弱于商店货）
3. **层数对应档位**：通关某 Boss 层 → 按该层对应 tier 掉该 tier 稀有装备：
   - 用装备重做 §3.6 的层门槛映射 `tier_of_layer(layer)`（如 ≥30→T1，≥80→T2，…，≥500→T5；T6 灭世 ≥2000、T7 至尊 ≥5000 为纯称号阶）；
   - 精英/小 Boss 掉 `tier_of_layer`，大 Boss 允许 `tier_of_layer + 1`（惊喜，D-B6）；
   - 同时满足 `掉落tier ≤ 玩家当前阶级(+超前允许)` 才掉，否则降档到可穿为止。

**职业(line) 约束**：只掉玩家当前职业可用（战士→physical，法师→magic，未转职→any）。

**稀有装备字段**：与普通装备同结构 + `"rare": true`（或独立表天然区分）+ `tier`，供展示与掉落过滤。

**独立命名规则**：
- 稀有装备使用**专属名字**，不与武器库/铁匠铺任何装备重名（例：武器库有“秘银剑”，稀有装就命名为“秘银之辉·星陨”，避免混淆）；
- 命名风格可带“·”后缀或传奇词缀（如 星辰/裂空/灭世/神铸），体现“掉落限定”稀有度；
- `id` 与名称在 `rare_drops.json` 中独立维护，商店查询天然查不到。

**展示标注（✦ 星号 + 稀有）**：
- 背包/播报/掉落播报中，稀有装备显示为 `✦ 名称(稀有)`（如 `✦ 星陨巨剑(稀有)`），前缀用星号强化“这不是商店货”；
- 在 `/背包`、掉落播报、地下城状态等处统一带星号；普通装备不带。

**掉落池**：优先 **独立 `rare_drops.json`**（商店表分离、天然不可购、便于维护与平衡），不再从 `_all_item_meta()` 筛商店货。

### 4.4 触发消息

通关 Boss 层（一次结算可能连过多层时逐层触发）收集掉落，
在地下城 `/地下城 状态` / 退出报告 / 或主动推进后首次交互时汇总播报：
例：`🎉 通关 第100层 大Boss「××」！掉落：金矿石×1、✦ 星陨巨剑(稀有) new！×1`

> 掉落装备**写入背包后立即可见**并带 `new！` 提醒（D-B11/D-B13）；本次结算**不改变推进速度**，
> **退出后下次进入自动计入生效**。播报可附：`（退出后再次进入地下城即生效）`。

## 八、实施步骤（建议顺序，依赖装备重做节奏）

1. 确认 §6 决策（D-B1~B13）。
2. `dungeon.py`：加 `boss_type`/`effective_layer_total`/`tier_of_layer`；接入结算循环。
3. 建 `rare_drops.json` 稀有装备池（数值满足强度钳制：同tier普通 < 稀有 ≤ tier+1普通；**独立专属命名**）。
4. 掉落函数：矿石走 `ore.grant_ores`；稀有装备从 `rare_drops.json` 按 §4.3 抽（层→tier、职业、阶级、钳制），写入时标 `is_new`。
5. 掉落汇总与播报（commands 地下城报告；**`✦ 名称(稀有) new！` 展示**）。
6. 平衡校验脚本断言稀有装备强度（与装备重做共享 `equipment_balance_check.py`）。
7. 回归：模拟 10/50/100 层推进——血量放大、通关掉落、跨层结算不漏、职业/阶级/强度钳制生效、商店买不到稀有、**掉落后入包立即可见+new！提醒，退出重进下次进入后计入生效（D-B11/D-B13）**、**稀有带✦与(稀有)标注**。
8. 展示层与 README 同步。

## 九、风险与注意

- **跨层结算**：`settle_dungeon` 一次可能连过数十层（离线久），每层都要判 Boss 与掉落，需防循环风暴（已有 `_MAX_SETTLE_LAYERS` 保护）。
- **掉落“穿不上”**：必须校验 tier≤当前阶（除 D-B6 允许的 +1），否则旧装备 bug 类似的“持有但不生效”会再现。
- **掉落生效节奏（有意设计）**：掉落装备“退出重进后下次进入才计入”（D-B11）；必须配 `new！` 提醒（D-B13），避免玩家误以为掉落丢失或未生效。
- **new 标记生命周期**：需在下次进入生效时可靠清除，避免长期残留误导（D-B13）。
- **稀有强度钳制**：稀有装备若超 tier+1 会挤压商店高级货；若弱于同 tier 普通则没存在意义 → 用平衡脚本断言 `同tier普通 < 稀有 ≤ tier+1普通`。
- **商店边界**：稀有池绝不能出现在 `/武器库` `/铁匠铺`（独立加载器隔离），避免“商店能买”违背定义。
- **数值膨胀**：Boss 层若倍率过高 + 掉落过肥，会加速通关与产币 → 与装备重做 §3.6 收益测算联动校验。
- **与定时矿石并存**：Boss 即时掉落与 400 层 15 分钟矿石互不干扰，但掉落播报需合并，避免刷屏（一次结算合并成一条）。
